## 1. 目标与非目标

**目标**

1. 三段时间片 + 休眠态，共四态；时间片与数值区间**全部可配**
2. 数值有实际后果：影响"要不要回、回多长、发不发图、什么语气"
3. 休眠：低于阈值自动进入，仅 @ 可唤醒，唤醒有好语气和大幅回能
4. 启动校验时间窗（重叠 / 覆盖 / 格式），配错直接 fail-fast
5. 能量与休眠态**持久化**，重启不丢

**非目标**：不改记忆、搜索、表情包收集、用量统计的任何逻辑。

## 2. 状态机（四态）

| 状态 | 进入条件 | 优先级 | 行为门槛 | 说明 |
|---|---|---|---|---|
| **休眠期** | `energy ≤ sleep.threshold`（默认 0.15） | 最高 | **非 @ 一律不回复，且不调 LLM**；@ 则立刻唤醒 | 只看能量，与时间片无关 |
| **疲倦期** | 时间片 `01:00–09:00` | 中 | ~~硬否决~~ **不拦截**（0.5.3 起）：非 @ 照常决策，语气按困倦写进 prompt | 只影响能量增减速度 |
| **平淡期** | 时间片 `09:00–17:00` | 中 | 正常决策 | 能量收支大致平衡 |
| **兴奋期** | 时间片 `17:00–次日 01:00` | 中 | 正常决策 | 恢复快、消耗低 |

时间片默认各 **8 小时**，正好对齐你的三段时间；休眠可发生在任意时间片，覆盖时间片状态。

## 3. 能量数值（默认值 + 依据）

所有区间都是**闭区间随机取值**（`uniform`），单位 0~1。

### 3.1 每次处理的增量

| 状态 | 未回复（idle_gain） | 回复消耗（reply_cost） | 被 @ 提升（at_boost） | 表情包概率（meme_prob） |
|---|---|---|---|---|
| 兴奋期 | **+0.06 ~ +0.14** | **0.03 ~ 0.08** | **0.10** | **55%** |
| 平淡期 | **−0.01 ~ +0.04** | **0.05 ~ 0.11** | **0.08** | **30%** |
| 疲倦期 | **0.00 ~ +0.02** | **0.12 ~ 0.20** | **0.05** | **10%** |
| 休眠期 | 见 3.2（按分钟恢复） | 唤醒回复按疲倦期下限 ×0.6 | **0.28**（唤醒专用） | **5%** |

**依据**：现版每批"回归 15% + 随机 ±0.08"在能量 0.3 附近约等于 +0.06；回复消耗典型值（20 字）≈ 0.07。上表让兴奋期体感接近现在的 0.7 基线，疲倦期明显更"贵"。

### 3.2 休眠参数

| 参数 | 默认 | 说明 |
|---|---|---|
| `threshold` | 0.15 | 能量跌到此值触发休眠 |
| `duration_minutes` | `[180, 300]` | **区间**：每次入睡从区间内随机抽样（更像生物）；`min ≥ 30`、`max ≤ 1440`、`min < max` |
| `recover_per_10min` | 0.02 | 睡眠期间每 10 分钟恢复（4 小时 ≈ +0.48） |
| `wake_boost` | 0.28 | 被 @ 强制唤醒的精力提升 |
| `wake_floor` | 0.55 | 自然醒时能量下限（避免刚醒就又要睡） |
| `drowsy_minutes` | 30 | 唤醒后"困倦期"，语气偏困、@ 提升减半 |

### 3.3 浮动与边界

- 全局噪声：`±0.01`（替代原来的 ±0.08，避免节律被随机淹没）
- 能量钳制 `[0.0, 1.0]`
- 回复消耗的长度因子：`cost = uniform(min,max) × (0.8 + 0.4 × min(1, 字数/60))`，长回复更费
- 移除"向基线回归"（由 idle_gain 的符号与大小承担），`AIGF_ENERGY_BASELINE` 标记为 deprecated（保留读入以兼容旧配置）

## 3.4 两层职责分离（重要）

| 层 | 决定什么 | 配置位置 |
|---|---|---|
| **时间片状态**（兴奋/平淡/疲倦） | **只决定能量怎么变**：`reply_cost` / `idle_gain` / `at_boost` | `states.*` |
| **能量档位**（四档；睡眠是独立状态，不属于档位） | **决定怎么回复**：语气文案、表情包概率与候选数量、回复倾向提示 | `levels[]` |

> 也就是说：凌晨两点不一定"说话很困"，只有当能量真的掉到低档时才会；反之白天也可能因为连续陪聊把能量耗到末档「有点懒」，再低就直接睡着。

### 能量档位默认值

| 阈值 | 档位 | 表情包概率 | 候选数 | 回复倾向提示基数 | 语气 |
|---|---|---|---|---|---|
| ≥0.80 | 精力充沛 | 55% | 20 | 0.55 | 看到什么都想插嘴，主动接梗 |
| ≥0.60 | 状态不错 | 45% | 16 | 0.38 | 有兴趣的话题会主动参与 |
| ≥0.40 | 一般般 | 30% | 12 | 0.25 | 有人找就回，不主动展开 |
| ≥0.20 | 有点懒 | 12% | 8 | 0.10 | 倾向潜水，回得很短 |

> 能量 ≤ `sleep.threshold`（默认 0.15）即进入睡眠态，不再属于任何档位；0.15~0.20 未入睡，按末档「有点懒」处理。

回复倾向提示（方案 C）：`p = reply_base + 0.60 × (energy − 0.5)`，钳制在 0~0.95，**只写进 prompt**（"对于没 @ 你的消息，你大概只有 25% 会接话"），不做任何硬性拦截。

## 4. 判定链路

```
收消息 → 攒批(现有) → gate1(休眠) → 构建 prompt(注入状态/语气/表情包概率/时间) 
      → LLM 决策 → gate2(疲倦低能量概率否决) → 发送 → 结算能量 → 落盘
```

**gate1（硬拦截）**：休眠期且本批无 @ → **直接丢弃本批**（不构建 prompt、不调 LLM，只记 debug 日志）。有 @ → 唤醒（`energy += wake_boost`，清 sleep_until，置 drowsy_until），继续正常流程，并在 prompt 里注入"刚才睡着了被叫醒"。

**gate2（硬否决）**：~~疲倦期非 @ 批次 → **直接丢弃，不构建 prompt、不调 LLM**（与休眠同级处理，只是被 @ 时语气不同）。被 @ 时正常回复，按疲倦期参数结算。~~
> **0.5.3 起已废弃**：硬拦截只属于睡眠态。疲倦期不再丢弃消息，非 @ 批次照常构建 prompt 并交给 LLM 决策（接话倾向按能量档位写进 prompt），prompt 中额外注入"深夜疲倦期，说话变蔫"的语气提示。设计依据：节律周期只影响**说话状态与能量增减**；"直接听不见"是睡眠独有的语义。`decision.tired_block_non_at` 配置项同步删除。

**表情包概率（按档位）**：构建 prompt 前按当前档位掷骰子（`meme_plan`）：
- 命中 → 注入该档位数量的候选（20/16/12/8/4）+ prompt 提示概率 → 模型从候选里挑
- 未命中 → **完全不注入候选**，并提示"这轮不要发表情包"；发送阶段白名单为空，任何 meme 项都丢弃（省 token、防幻觉）
- 被 @ 时概率 +0.15（可配）；单条回复最多 1 张

## 6. 时间窗校验（启动 fail-fast）

规则：

1. 格式必须是 `HH:MM`（24 小时制），`start != end`
2. 允许跨零点（`start > end` 时视为 wrap）
3. **任两段不得重叠**（含边界端点；`09:00` 归后一段）
4. 三段必须**正好覆盖 1440 分钟**；缺口 → 报错（或 `strict=false` 时缺口回退平淡期 + 告警）
5. 每段最短 30 分钟

错误示例（直接拒绝启动，日志指出具体冲突）：

```
[energy] 配置校验失败：兴奋期(17:00-01:00) 与 疲倦期(00:00-08:00) 重叠 00:00-01:00
[energy] 配置校验失败：未覆盖 08:00-09:00（缺口 60 分钟）
```

## 11. 风险与对策

| 风险 | 对策 |
|---|---|
| 休眠让群友以为 bot 挂了 | `状态` 可查剩余时间；被 @ 必醒；日志记休眠起止 |
| 硬 gate 与"必须 @ 才回"的现有规则打架 | 明确优先级：休眠 > @ 回复 > 时间片状态 |
| 用户把时间窗配错导致全天不回复 | 启动 fail-fast + 错误信息指向具体段；`重载节律` 失败保留旧配置 |
| 能量通胀（兴奋期一直涨到 1.0） | 上限钳制 + 回复消耗下限，长时间聊天仍会掉能量 |
| 重启频繁导致节律被打断 | 已持久化；休眠中重启继续睡 |
| token 成本上升（语气/概率注入变长 prompt） | 注入约 60~100 字，占现有 prompt 的 2% 以内 |

## 12. 表情包机制现状（原项目实现）

| 环节 | 实现 | 参数 |
|---|---|---|
| 库存 | 管理员库 `memes.json` + 自动收集 `collected.json`，每条含 `id/description/keywords/usage_count/last_used` | — |
| 候选注入 | `select_candidates(对话文本, limit)`：关键词命中 +2 分、描述分词命中 +1 分；命中按分排序取前 N，不足用 `usage_count` 最高的补齐 | `AIGF_MEME_CANDIDATES=20` |
| 决策 | **完全由 LLM 自由裁量**：prompt 只给格式（`{"type":"meme","id":"..."}`）与"不要在正文提 id"，**没有任何"何时该发/发多少概率"的指令** | — |
| 发送 | 解析 `vmeme` 项 → `meme_manager.resolve(id)` → 取文件；`_recent` 列表去重近期发过的 id（默认窗口内不重复） | `_recent_max` |
| 频次 | `resolve` 时 `usage_count += 1`，仅用于清理淘汰与候选补足排序，**不参与发送概率** | — |

**缺陷**：没有节律/能量联动、没有概率控制、可能连发或不发、候选只看文本相似度而不看"当前心情"。

## 13. 决策记录（4 项已确认）

1. ✅ **配置载体**：结构化 `energy.json`，**JSON 覆盖 `.env`**（优先级：默认 < .env < JSON）
2. ✅ **休眠时长**：区间 `[180, 300]` 分钟，每次入睡独立随机抽样
3. ✅ **表情包策略**：**概率前置触发 + 模型选图 + 单张上限 + 白名单校验**（非硬裁剪）
4. ✅ **疲倦期门槛**：~~硬否决~~ → **0.5.3 起改为不拦截**（硬拦截只属于睡眠态；疲倦期只影响语气与能量结算，见上文 gate2 的废弃说明）
5. ✅ **决策方式**：A（不设概率门，模型裁量）+ C（把回复倾向估算写进 prompt）
